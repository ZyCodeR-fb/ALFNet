# LF/SUP bounded development design

This document freezes the implementation before any candidate result is read.
Neither candidate changes the data split, target, full-N exposure contract,
GRIN path, ALFTemporal, FiLM fusion, hidden width, depth, optimiser or early
stopping rule.

## LF: low-flow safe-relative objective

Raw MAPE is unsuitable as a training loss because its denominator and gradient
are unbounded near zero. LF instead adds

`0.05 * |y_hat-y| / max(|y|, q10_positive_train_known)`

in original flow units. The floor is fitted once from positive targets inside
the training window and training-known node set. The elementwise term uses the
same lifecycle-role balancing as the existing ALFNet squared-error objective.
It is flow-only; speed configs fail if they enable it. The 0.05 coefficient is
fixed here before development results are opened. BASE uses 0 and is exactly
unchanged. LF is not added to MoGERNN because it is an ALFNet method candidate,
while evaluation data, masks and headline metrics remain identical.

## SUP: distinct directed multi-scale propagation

DCRNN motivates directed forward/backward random-walk diffusion; MixHop shows
why retaining separate adjacency powers exposes genuinely different
neighbourhood scales. SUP therefore starts from the ordered inventory:

1. identity;
2. binary neighbour mean;
3. forward one-hop random walk;
4. backward one-hop random walk;
5. forward two-hop random walk;
6. backward two-hop random walk.

The matrices are constructed from the frozen propagation graph. A stable
float64 CPU pass removes numerical duplicates in that order before model
construction. Symmetric graphs therefore do not pretend forward and backward
are different experts; directed graphs retain the distinction. The expert
count and router tensors are derived from the resolved inventory, and the
names are emitted with router diagnostics. There is no learned test graph,
node-ID embedding or topology access beyond the shared frozen graph contract.

The existing soft lifecycle router and its load-balancing auxiliary are kept.
The optional ALFNet evidence router was a second, unused routing mechanism and
has been deleted rather than turned into another candidate.

Primary design sources:

- DCRNN: <https://arxiv.org/abs/1707.01926>
- MixHop: <https://arxiv.org/abs/1905.00067>
- GMoE: <https://proceedings.neurips.cc/paper_files/paper/2023/hash/9f4064d145bad5e361206c3303bda7b8-Abstract-Conference.html>

## Why this does not promise ST-FiT-scale Unseen errors

ST-FiT is relevant evidence that much lower unknown-node errors are possible,
but it is not an apples-to-apples result. Its reported protocol fixes a small
observed-node subset and combines temporal data augmentation with learned
sparse topology, whereas this repository evaluates dynamic lifecycle events,
disjoint validation/test unseen sets and a fixed shared graph contract. LF can
address low-flow relative error; SUP can improve multi-hop spatial transfer.
Neither implements ST-FiT's temporal augmentation or topology learner. Adding
those would be a separate major architecture study and is explicitly deferred
until the bounded BASE/LF/SUP/LF+SUP experiment is evaluated on validation.

ST-FiT source: <https://ojs.aaai.org/index.php/AAAI/article/view/33310>

## Frozen first development comparison

Dataset: PEMS08; seed: 32; validation only. Candidates are BASE, LF, SUP and
LF+SUP for ALFNet plus one unchanged MoGERNN control. Candidate YAMLs are
generated by `scripts/build_v4_lf_sup_candidates.py`. No short or complete
training starts as part of this implementation change.
