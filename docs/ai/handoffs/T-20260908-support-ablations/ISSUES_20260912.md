# ALFNet 两数据集优化前问题清单 — 2026-09-12

任务：`T-20260908-support-ablations`。这是现有证据的诊断与交接，不是新实验结果或已批准的新模型方案。本文路径均相对仓库根目录。代码版本及文件哈希见同目录 `CHECKPOINT_20260912.json`。

## 1. 判断摘要

当前 ALFNet 的问题不是整体预测已经落后 MoGERNN，而是整体优势未覆盖所有观测条件，且显式状态和动态传播的收益不稳定。优先关注：**PEMS-BAY 的 Unseen、两数据集的相对误差 MAPE、METR-LA 早期接入、Full 相对内部控制的退化**。跨节点时间上下文有较一致的消融支持，应避免为修复局部指标直接删掉它。

用户希望后续优化仅使用 METR-LA、PEMS-BAY，并尽量各项超过 MoGERNN。这是优化目标，不是已经实现或能够保证的结果。主表 LifeAvg 三指标目前已经全部超过 MoGERNN；若目标包括主条件和阶段，则目前还有以下四个落后单元。更广的“所有基线、所有条件均最优”尚未实现，不能用减少对照或改变指标口径获得。

| 数据集 | 变体 | MAE | RMSE | MAPE |

| METR-LA | Full | 4.638117 | 6.806835 | 14.626242 |
| METR-LA | Mask-only | 4.818333 | 6.942033 | 14.381948 |
| METR-LA | Static Propagation | 4.914450 | 7.032559 | 14.610369 |
| METR-LA | Local Temporal Context | 5.034644 | 7.072306 | 14.665492 |

- METR-LA：Mask-only 的 MAPE 比 Full 低 1.67%，静态传播低 0.11%；Full 的 MAE/RMSE 优势不能解释为三指标一致受益。

### 2.4 配对干预与 q/layout 揭示的边界

正文图 3 是 **64 个验证 held-out 节点窗口、23 个节点**，已知节点 64 窗口/53 节点放附录；不能混成一个归纳结论。

- held-out 的完整历史轨迹：Full 的 MAE 3.7134，高于 Mask-only 3.5742；Full 相对降低为 **−3.89%**。Join-6：4.0286 对 3.9040，为 **−3.19%**，且这两条轨迹中 Full 的 RMSE/MAPE 也更差。
- held-out Join-3：Full MAE 较好，但 RMSE/MAPE 较 Mask-only 差。故“显式状态在所有接入轨迹有效”不成立。
- held-out Fault-6、Outage：Full 相对 Mask-only 的 MAE 降低约 8.61%、8.39%，故状态收益有明确条件依赖，而不是整体无用。
- held-out Outage 对 MoGERNN：Full MAE 6.2661 对 6.3311，仅改善 1.03%；RMSE 10.0298 对 10.0326 近似持平；MAPE 23.0071 对 21.6618，反而较差。混合 known/held-out 平均会掩盖此弱点。
- q/layout 原汇总使用 128 配对窗口（known/held-out 各 64）。q=0 时 Full 对 MoGERNN 的 MAE 降低约 3.95%，MAPE 却较差约 3.50%；q=3 Early 的 MAE 收益仅约 0.17%，MAPE 较差约 5.96%；q=6 Early 的 MAPE 也较差约 1.22%。历史数量相同不等于有效支持相同。
- Join 表示接入，不等同于经历故障后的恢复。现有六轨迹没有隔离完整“失效→恢复”循环；恢复能力不足目前是合理假设，不能写成已经测得的事实。
- 干预仅从自然完整 12 步历史及未来中选样，保留固定节点/起点/目标/非干预输入；它不代表自然缺失窗口总体。q 研究固定成熟活动角色 AAS 与 age=1。预测响应已测，内部 routing/FiLM 因果贡献尚未单独测得。

## 3. 遗留机制问题：哪些是缺陷，哪些是设计选择

### 3.1 support 算子冗余确有代码依据，但优化收益未建立

`layers/lifecycle_moge.py::_candidate_supports` 的当前 BASE 是 identity、二值 mean、weighted_mean、forward_diffusion、backward_diffusion。`layers/gnn.py::calculate_random_walk_matrix` 与 weighted_mean 都做加权邻接行归一化；通常对应同一算子（实现的零行/微小度数处理及浮点差异应另行核验）。若邻接对称，反向也可能重合；本轮没有重新测两数据集矩阵的数值距离，不能直接报告“五个都是独立专家”或“两图恰有几个独立算子”。

这是算子解释性与路由可辨识性问题：重复算子的权重可以互相转移，门控变化不一定意味着实际传播变化。它不自动证明预测受损。把算子换得更不同还会改变传播尺度和优化难度，过去失败已有证据。下一步应先量化重复/有效混合，而不是再无差别替换 SUP 配方。角色 one-hot/age/mask 的信息相关性是另一问题，不应与算子矩阵冗余混称。

### 3.2 dense soft routing 与单预测分支不是固有缺陷

两数据集当前使用 soft 路由，所有算子稠密加权。代码在应用权重前已算全部 support，改为 hard/top-k 并不自动省计算。历史 noisy_topk 的 k=1 对单元素 softmax 的预测梯度为零，不能仅为“稀疏专家”叙事回退该实现。soft 是保持可训练性的合理选择。

有效信息流是共享历史重建、图递归预测、时间分支输出上下文特征经 FiLM 调制图预测、输出图细化；不是两个独立预测的混合。状态条件化的 **专家路由** 位于 ALFGraph；角色/年龄/mask 还用于重建、时间表示和细化缩放，不能说状态只影响 ALFGraph。ALFTemporal 的 latent router 是注意力结构，不是另一套生命周期专家路由。

真正待判断的是：条件化是否在无历史/早接入时产生负迁移、静态先验是否更稳、有效算子选择是否有区别。两数据集消融支持对这些问题排查，不支持为了模块数量增设 router 或双预测头。

### 3.3 patch 是容量，不是分区数；补齐 token 不是零填充

METR-LA 最大原始分区大小为 7、采用容量 8；PEMS-BAY 最大为 11、采用容量 11。`spa_patchnum` 来自实际 layout_parts，容量与分区数量是两个参数。旧文档“一多一个分区”表述错误。

`model/ALFTemporal/ALFTemporal.py::_reorder_data` 为不足容量的分区按邻接排序补入实际节点索引。因此改变容量会改变上下文 token 和重复暴露，不只是无效 padding。实现将分区内边权设零后参与排序，并非布尔排除所有分区内索引；在零权重并列等边界下是否选到分区内节点，尚未实测。

用户先前冻结 METR-LA=8 是当前基准设置，不是已证全局最优。**没有必要为了论文形式先穷举每个数据集最优分区数**。是否调容量应与 Unseen/接入缺口的机制证据关联；容量和重新划分布局不能在同一比较中混改。任何后续选择都需独立验证计划，保留当前 Full。

### 3.4 MAPE：当前是低速度，不是低流量

METR-LA/PEMS-BAY 预测速度 v（payload channel 2）。低分母放大相对误差在数学上成立，但现有汇总尚未证明 MAPE 弱点主要由低速度样本驱动，更不能把历史 flow 数据集的问题直接迁移成解释。

当前 role-balanced MSE 训练与按 validation LifeAvg MAE 选 checkpoint 并不直接优化 MAPE。它可能与 MAE/RMSE/MAPE 的取舍有关，属于待验证原因。也需区分系统偏差、少量小分母样本和条件分布差异。不得事后调整 epsilon、排除低值或偷换选模规则来达成指标领先。

### 3.5 额外代码与证据问题

- `ALFNet._state` 执行 state_encoder，但 forward 丢弃其 state 输出，仅保留 last_availability；该 encoder 不在有效预测依赖中。它还在 optimizer 剩余组中，不能把该组统称新的条件化机制。可能有无效计算/参数计数问题，但不等于已经发现可提升精度的模块；清理需考虑初始化 RNG、checkpoint 兼容性，不在本轮修改。
- optimizer 的三组分别为图分支+共享重建、时间分支、其余 FiLM head/graph_refiner/state_encoder；不能将第三组名称解释为完整独立模型模块。
- 当前证据是 seed32 validation/mixed-source。多轮围绕同一验证集调整有选择偏差风险；“所有单元领先”不保证新种子或未见样本稳定。新阶段需保留原始 Full 和失败结果，不以不断缩小对照集合定义最优。
- 主表 LifeAvg 平衡汇总与配对分析的窗口/预测步 pooled RMSE 不是同一算式，不能直接横比数值。
- `outputs_v4/reports/observation_support_v1/README.md` 仍有“Main figures average 128”旧句；最新 figure_manifest 与 paper 附录已明确图 3 只取 held-out 64。当前交接以最新 figure_manifest 和实际绘图脚本为准，本轮未修改既有输出。

## 4. GWNet 的实际证据与可参考边界

当前九模型主表不含 GWNET，因此不能将“主表最强 MoGERNN”进一步扩展为“全仓库最强”。目前已有 corrected-baseline 的 PEMS-BAY GWNET 与 ALFNet 完整生命周期结果如下：

| 状态 | ALFNet MAE | GWNET MAE | ALFNet RMSE | GWNET RMSE | ALFNet MAPE | GWNET MAPE |
|---|---:|---:|---:|---:|---:|---:|
| Unseen | 5.009514 | 5.083539 | 7.135150 | 7.499952 | 14.131390 | 13.539070 |
| Steady | 2.073156 | 1.905139 | 3.347362 | 3.265661 | 4.852753 | 4.364340 |
| Join | 2.432881 | 2.422564 | 4.020754 | 4.137020 | 6.370869 | 5.891689 |
| Fault | 2.643365 | 2.524152 | 4.048115 | 4.092131 | 6.629244 | 6.164332 |
| LifeAvg | 3.039729 | 2.983848 | 4.637845 | 4.748691 | 7.996064 | 7.489858

结果表明，两种模型不存在跨状态、跨指标的一致优劣关系。**ALFNet 在 Unseen 阶段的 MAE 和 RMSE 分别优于 GWNET 约 1.46% 和 4.86%，说明其在完全未见节点上的预测误差控制具有优势；GWNET 则在该阶段取得更低的 MAPE。**进入 Steady 阶段后，GWNET 在 MAE、RMSE 和 MAPE 三项指标上均优于 ALFNet，优势分别约为 8.82%、2.50% 和 11.19%。

Join 与 Fault 阶段进一步呈现指标上的互补性：GWNET 在两个阶段均取得更低的 MAE 和 MAPE，而 ALFNet 分别取得约 2.81% 和 1.08% 的 RMSE 优势。因此，GWNET 更擅长降低平均绝对误差和相对误差，而 ALFNet 在部分生命周期转换状态下对较大误差的抑制更好。

从 LifeAvg 看，GWNET 的 MAE 和 MAPE 分别比 ALFNet 低约 1.87% 和 6.76%，但 ALFNet 的 RMSE 比 GWNET 低约 2.33%。因此，现有 PEMS-BAY 证据只能说明 GWNET 是一个具有竞争力且值得重点参考的强基线，不能表述为 GWNET 全面优于 ALFNet，更不能表述为三项指标均最优。与此同时，目前尚未在已确认的完成结果中获得 METR-LA 对应的 GWNET validation 结果，因此也不能宣称这一结论已经在两个数据集上得到一致验证。

从结构上看，本地 GWNET 实现保留了门控膨胀时间卷积、残差/skip 连接、扩散传播以及自适应支持等核心机制；为满足当前任务的归纳约束，原始依赖训练节点身份的节点 ID 因子被替换为共享结构编码。因此，其结果可以用于分析不同时间建模和传播机制在生命周期预测中的作用，但不能简单等同于原始 transductive GWNet 的能力。

此外，docs/comparison_model_audit.md 已记录 GWNET 使用 masked MAE，而 ALFNet/MoGERNN 使用 MSE 训练的目标函数差异。因训练目标、结构设计和归纳约束均不完全一致，当前性能差异不能直接归因于某一个网络组件。

因此，从 GWNET 中可借鉴的内容目前只能作为待验证的机制假设：例如，门控膨胀时间卷积是否能够更充分利用稀疏或陈旧历史，多尺度时间感受野与 residual/skip 路径是否有助于降低 Join/Fault 等生命周期转换阶段的预测偏差，以及这些机制为何在 Steady 状态表现较强、却没有在 Unseen 状态的 MAE/RMSE 上超过 ALFNet。上述问题均需要通过受控消融实验验证。

现阶段不应直接将整套 GWNET 模块拼接进 ALFNet，再根据最终涨分反向解释原因；也不能未经验证便将性能差异归因于“直接预测优于 AR”或“AR 误差累积”。任何后续融合都应首先提出明确机制假设，再通过最小模块替换和状态分层评测验证，同时避免重新引入训练节点专属 embedding，从而破坏当前模型的归纳设定。

## 6. 下一阶段优先级（未开始，不是已定实验方案）

1. **P0：Unseen 与 MAPE 缺口归因。** 先区分低速度、支持不足、节点泛化与误差偏置，再选改动；先守住当前 LifeAvg MAE/RMSE 优势。
2. **P0：条件化负收益。** PEMS-BAY 的 Full vs Mask-only/static，以及 METR-LA held-out 的 Full-history/Join-6，必须纳入候选检验，不能只报告收益轨迹。
3. **P1：早接入与旧历史利用。** METR-LA Cold/Warm 对 FCLSTM/STGODE，以及 q 小且 Early 的现象；故障后恢复单列为尚无直接证据。
