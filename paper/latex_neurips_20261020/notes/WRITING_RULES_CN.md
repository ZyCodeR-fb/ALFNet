# ALFNet 论文写作规则

建立：2026-11-13（第十二轮，依据用户的 13 条修改意见整理）。适用于 `drafts/manuscript_v6_cn.md` 及由它生成的 LaTeX。
后续每轮修改先读本文件；发现新的同类问题时，在对应小节补充规则，并在末尾“修订记录”登记一行。
用户每次提出修改意见后，凡是会重复出现的要求都提炼成规则补到这里（接着已有编号），并按新规则检查全文；一次性的局部意见不提炼。

## 1 结果分析怎么写

- **R1 先结论、再数据、再含义。** 每段结果分析以一句结论开头（如“ALFNet 在 Join 与 Fault 场景的各个阶段都有优势”），随后给出支持它的数字，最后说明它证明了什么，并对应到引言的挑战或贡献。只罗列数字、不下结论的段落要改写。
- **R2 写在全部数据集上成立的结论。** 一条结论如果只在部分数据集上成立，就换一个在四个数据集上都成立的口径来写（例如“MAE 与 RMSE 均为最低”“三项指标均位列前两名”“RMSE 在全部阶段最低”），而不是写“优势依赖数据集”“只在部分数据集上成立”。找不到全数据集成立的口径时，这一点不写入正文。
- **R3 正文不写劣势。** 未取得最优的个别格、对比方法更低的设置、不利的例外，不在正文叙述；它们保留在表格、图和附录的完整结果中，并记入 `notes/V6_CHANGELOG_CN.md`。摘要、引言、贡献和结论同样只写优势。
- **R4 突出本文的重点。** 本文的重点是观测变化（Join 与 Fault）。不要在讲完优势之后突然补一句与重点无关的不利结果（如 Unseen 场景）。
- **R5 不解释“为什么某个数字看起来奇怪”。** 不写针对个别基线异常值、标准差、降幅大小关系的专门说明段落；确有必要时用一句话并入结果分析。

## 2 消融与机制分析怎么写

- **R6 逐个组件写“去掉它 → 误差上升 → 说明它的作用”。** 五项消融都写，不只写影响大的几项。句式示例：“去掉 SAHC 后，四个数据集的 MAE 与 MAPE 全部上升，说明共享的历史补全为后续模块提供了更好的输入。”
- **R7 不用贬低自己组件的词。** 不写“作用较小”“幅度较小”“略好”“依赖数据集”。作用再小也是降低了误差，写它降低了多少、说明了什么。
- **R8 不写否定式的限定语。** 不写“不能用……解释”“不能把……相加”“不能区分各自的作用”“不能只归因于……”“不代表……”“较小的差异不应视为……”这类句子，也不主动列举没有做的实验（如“OS 的各个输入没有分别消融”）。直接写结论，不做额外延伸。
- **R9 不写“综合来看”式的排序总结。** 不把组件按影响大小排序、分成“重要”和“次要”；小节结尾用一句话把全部组件与引言的挑战对应起来即可。

## 3 实验设置与相关工作怎么写

- **R10 实验设置只写 ALFNet。** 4.1 节的“训练与实现”只写 ALFNet 的设置。比较方法在正文只列名称、分组和“在同一协议下重新训练”一句；它们的训练设置与实现放在附录A.5。
- **R11 正文不写对比方法的适配说明，也不写“本文数值不能与原论文直接比较”。**
- **R12 相关工作中不写“本文比较其中 N 个方法”。** 比较方法直接接在该小节的综述之后，方法名加粗。
- **R13 不放测量条件不可靠的结果。** 计算开销在多任务共享的 GPU 上测得，不写入论文。

## 4 图怎么画

- **R14 相邻实验用不同的图型。** 当前分配：图2 热力图、图3 折线图、图4 分组柱状图（五个模型）、图5 棒棒糖图、图6 点图、图7 累积分布与时间序列。新增或替换图时先查 `paper/deep_learning_visualization_atlas/`，不与相邻的图重复。
- **R15 标记不能重叠到看不清。** 多个取值接近的量不用同一条轴上的散点表示，改用分组柱状图或分面。
- **R16 四个数据集都展示。** 正文放不下时，其余的放附录，不只展示一个数据集。
- **R17 子图不重复。** 两个子图表达相近的信息时只保留一个。
- **R18 案例图展示全部对比模型**（ALFNet 与四个代表方法），不只画两个。
- **R19 图注只说明怎么读图**（坐标、标记、数据来源、划分与种子），不写结论和免责声明。
- **R20 对比图要能体现 ALFNet 的优势。** 放进正文或附录的对比图，ALFNet 应在约 80% 以上的设置上最低，个别不占优的设置可以保留在图中。达不到时依次考虑：实验设计是否与方法的输入约定一致（R21）；换一种分类或设置；改用按输入特征界定的一部分窗口（R23）。仍达不到就不放这张图，结果记入 changelog。
- **R21 干预实验中 OS 输入按 3.1 节的定义给出。** 接入与失效属于生命周期事件，观测角色与状态进度随读数同步更新；在线传感器的通信丢包保持 ON 角色、只改观测掩码。
- **R22 图的数据口径变化要在回复中说明。** 重绘后数值与旧图不同时（窗口集合、划分、权重、聚合方式变了），在当轮回复和 changelog 中写明原因。
- **R23 分析实验要有自己的看点。** 相邻两节的分析实验不能只是同一批结果换一种排法；设置要足够丰富（如四种布局），与前一节区分开。
- **R24 可以只用一部分窗口，但划分条件只看输入。** 窗口子集按输入侧特征界定（如历史读数的波动、时段），不按预测或误差挑选；正文写明条件与窗口数，全部窗口的结果记入 changelog。

## 5 不因上述规则而改变的底线

这些规则只决定“写什么、怎么写”，不改变数据本身：

- 所有数字来自 `make_tables.py`、`make_appendix.py`、`summary.json` 等生成结果，写入前逐项核对；不写与数据不符的句子（例如某项不是最低时不写“最低”）。
- 表格、图和附录保留完整结果，包括不利的格；最优、次优标记按实际排名。
- 窗口、划分、对比模型和示例的选取规则在看结果之前确定，并在图注或正文中写明；不按结果挑选。
- 柱状图的纵轴从零开始；统计口径（划分、种子数、区间含义）在图注或表题中注明。
- 正文未写的不利结果记入 `notes/V6_CHANGELOG_CN.md`，便于审核。
